## 1. 데이터 처리

### 1.1 Skeleton 정규화 — 논문에 전혀 없음

논문은 YOLOv11-Pose가 뽑은 17개(전처리 후 12개) 관절을 ST-GCN/LSTM에 넣는다고만
합니다. 그런데 픽셀 좌표를 그대로 넣으면 카메라에서 2 m 떨어진 고객과 4 m 떨어진
고객이 같은 행동을 해도 전혀 다른 입력이 됩니다. 정규화 방식은 성능을 좌우하는데
논문에 없습니다.

세 가지를 구현하고 설정으로 고를 수 있게 했습니다 (`sequence.normalize`).

| 모드 | 방식 | 성질 |
|---|---|---|
| `torso` **(기본)** | 엉덩이 중점으로 평행이동, 몸통 길이와 어깨 너비 중 큰 값으로 나눔 | 위치·크기 불변 |
| `bbox` | 사람 박스 원점 기준, 박스 크기로 나눔 | 박스 검출 품질에 민감 |
| `none` | 프레임 크기로만 나눔 | 화면 내 절대 위치 유지 |

기본을 `torso`로 한 이유는 두 가지입니다. 상단 시점에서는 몸통이 짧게 투영되므로
몸통 길이만 쓰면 스케일이 불안정한데, 어깨 너비와 최댓값을 취하면 이 문제가
사라집니다. 또 사람이 프레임 가장자리에서 일부 잘려도 어깨와 엉덩이만 보이면
정규화가 성립합니다.

클립 전체에 하나의 스케일(프레임별 스케일의 중앙값)을 적용합니다. 프레임마다
다시 정규화하면 팔을 뻗을 때 몸 전체가 수축하는 것처럼 보여 동작 정보가 사라집니다.

### 1.2 학습 데이터 증강 — 논문에 없음

논문은 증강을 언급하지 않습니다. 천장 카메라는 "위쪽"이 정해져 있지 않으므로
회전 증강이 자연스러워 보이지만, 실제로는 카메라와 선반이 고정이라 고객이 선반에
접근하는 방향이 어느 정도 제한됩니다. 회전 범위를 얼마로 할지는 측정해서 정했습니다
(EXPERIMENTS.md §1).

기본값: 회전 ±30°, 스케일 ±15%, 좌표 지터 0.01, 좌우 반전 확률 0.5.
반전 시 좌/우 관절을 서로 맞바꿔 해부학적으로 유효한 골격을 유지합니다.

### 1.3 train/validation 분할 단위 — "70/30"만 명시

논문 표 4.3은 클래스별 train/validation 프레임 수를 주지만 무엇을 기준으로 나눴는지
쓰지 않습니다. 프레임 단위로 무작위 분할하면 30프레임 윈도우가 크게 겹치기 때문에
거의 같은 시퀀스가 양쪽에 들어가고 검증 정확도가 부풀려집니다.

**데이터셋은 자체 split을 제공합니다.** ReadMe에 따르면 피험자 1–20이 학습(60개
영상), 21–26이 검증(18개), 27–41이 테스트(28개)입니다. 논문의 70/30과 다르지만,
MERL Shopping에 대해 발표된 수치들은 이 split을 기준으로 하므로 비교 가능성이
유지됩니다. 추출 단계에서 `--split train|val|test|trainval`로 고를 수 있습니다.

- 권장: 데이터셋 공식 split (`car.datasets.merl.split_official`)
- 기본: **클립 단위** 무작위 분할 (`--split-by clip`)
- 피험자 단위 분할 (`car.datasets.merl.split_by_subject`)
- 논문을 문자 그대로 읽는 `--split-by window`

### 1.4 윈도우 라벨 결정 — 논문에 없음

30프레임 윈도우가 두 행동에 걸칠 때 어느 라벨을 쓸지 문제입니다.
기본은 **마지막 프레임**입니다. 실시간 추론에서 모델이 답해야 하는 것은
"지금 이 사람이 무엇을 하고 있는가"이고, 이것이 학습과 추론의 조건을 일치시킵니다.
`build_windows(label_mode="majority")`와 `drop_mixed=True`도 제공합니다.

### 1.5 "Standing" 클래스

논문 표 4.3은 5개 클래스만 세지만, 혼동행렬(그림 4.2)에는 "Standing" 행/열이
있습니다. MERL의 background(어떤 행동 구간에도 속하지 않는 프레임)에 해당합니다.
기본은 5개 클래스이고, `include_background: true`와 추출 시 `--keep-background`로
6개 클래스 모드를 켤 수 있습니다.

### 1.6 Pose 라벨 제작 방법 — "YOLO 포맷을 이용해 제작"

126,350장을 수작업 라벨링했다고 보기는 어렵습니다. 큰 pose 모델(`yolo11x-pose`)을
교사로 써서 pseudo-label을 만들고 nano 모델을 파인튜닝하는 방식으로 구현했습니다
(`tools/autolabel_pose.py`). 교사는 신뢰도 0.6 이상, 프레임당 가장 확실한 한 명만,
확신 관절 8개 이상인 프레임만 채택합니다. 잘못된 라벨이 없는 라벨보다 나쁘기
때문입니다.

## 2. 모델 구조

### 2.1 ST-GCN grouped convolution 그룹 수 — 숫자 없음

논문은 "grouped convolution을 통해 연산 효율성을 극대화"한다고만 하고 그룹 수를
밝히지 않습니다. 논문의 파라미터 수 922,301개에서 역산을 시도했습니다.

| groups | 파라미터 수 | 논문 대비 |
|---|---|---|
| 1 | 1,983,021 | +115% |
| **2 (기본)** | **1,018,413** | **+10.4%** |
| 4 | 535,725 | -42% |
| 8 | 294,573 | -68% |

groups=2가 가장 가깝습니다. 정확히 맞지 않는 이유는 논문이 시간축 커널 크기도
밝히지 않았기 때문입니다(기본 9 사용). `stgcn.groups`와 `stgcn.temporal_kernel`로
조정할 수 있습니다.

### 2.2 ST-GCN 세부 — 논문 그림 3.1에 없는 것

| 항목 | 결정 | 근거 |
|---|---|---|
| 시간축 커널 | 9 | 원 ST-GCN 논문 기본값 |
| LeakyReLU 기울기 | 0.1 | 일반적 기본값 |
| 그래프 분할 전략 | spatial (3분할) | 원 ST-GCN의 기본 |
| residual 연결 | 첫 블록 제외 사용 | 6층에서 학습 안정성 |
| stride | 채널이 늘어나는 블록에서 2 | 시간 해상도와 채널 폭의 균형 |
| edge importance | 사용 | 관절별 중요도 학습 |

### 2.3 LSTM Dense 레이어 폭 — 논문 그림에 폭 표시 없음

그림 3.2는 `Dense → LeakyReLU → Dropout → Dense` 블록만 보여줍니다.
논문의 파라미터 수 352,775개에 맞추어 **32**로 정했습니다. 결과 353,549개,
논문 대비 +0.2%입니다.

### 2.4 입력 채널

논문 그림 3.1에 `3 channel (x, y, s)`라고 표시되어 있어 그대로 (x, y, score)
3채널입니다. 속도(프레임 간 차분)를 추가하는 6채널 모드도
`sequence.use_velocity`로 제공하지만 기본은 끔 — 논문 구조를 따릅니다.

## 3. 학습 설정

논문 표 4.2가 주는 것: epoch 300, batch 128, dropout 0.25, Adam, CCE, early stop.
주지 않는 것:

| 항목 | 결정 | 근거 |
|---|---|---|
| learning rate | 1e-3 | Adam 기본값 |
| LR 스케줄 | cosine annealing (→ 1e-5) | 300 epoch에서 후반 수렴 안정 |
| weight decay | 1e-4 | 작은 모델의 일반적 값 |
| early stop patience | 30 epoch | "Enabled"만 명시됨 |
| early stop 기준 | validation accuracy | 논문이 정확도 중심으로 보고 |
| gradient clipping | L2 norm 5.0 | LSTM 학습 안정화 |
| 윈도우 stride (학습) | 5 | 거의 같은 윈도우 중복을 1/5로 줄임 |
| 클래스 가중치 | 기본 끔 | §7.0 참조 — 실제 데이터는 불균형 |
| 클래스 균형 맞추기 | `balance_ratio` | 논문이 "균등하게 설계"했다고만 밝힘 |

## 4. 추적

### 4.1 StrongSORT ReID 네트워크 — 명시 없음

논문은 StrongSORT의 re-identification 손실(식 5, 6)을 설명하지만 어떤 ReID 망을
썼는지 밝히지 않습니다. ReID 망을 추가하면 온디바이스에서 두 번째 신경망이 매
프레임 돌아가므로 비용이 큽니다.

- 기본: **HSV 색 히스토그램** (`tracker.appearance: histogram`). 모델 없이
  동작하고, 옷 색이 다른 두 고객을 구분하는 실제 상황에는 충분합니다.
- 선택: `reid` + `tracker.reid_weights`에 TorchScript ReID 모델 경로.
- 선택: `none` — motion(Kalman)만 사용. 가장 가볍습니다.

### 4.2 StrongSORT 하이퍼파라미터

논문이 주는 것: `n_init = 3` ("3회 연속 매칭 성공 시 Confirmed"), max_age 존재.
나머지는 StrongSORT 원 논문의 값을 따랐습니다.

| 항목 | 값 | 출처 |
|---|---|---|
| max_age | 30 | CHOICE — 버퍼 길이와 맞춤 |
| max_iou_distance | 0.7 | StrongSORT 기본 |
| max_cosine_distance | 0.2 | StrongSORT 기본 |
| EMA alpha | 0.9 | StrongSORT 논문 |
| motion/appearance λ | 0.98 | StrongSORT 논문 |
| NSA Kalman | 사용 | StrongSORT 논문 |
| ECC 카메라 보정 | 미사용 | 천장 고정 카메라에는 불필요 |

## 5. 추론

### 5.1 30프레임 버퍼의 단위 — 논문이 암시만 함

논문은 "30 프레임의 시간적 정보를 버퍼링"한다고 합니다. 추적기가 있으므로
버퍼는 **트랙별**이어야 합니다. 프레임 단위 버퍼 하나를 쓰면 매장에 두 명이 있을 때
두 사람의 자세가 한 시퀀스에 섞입니다.

### 5.2 예측 평활화 — 논문에 없음

프레임마다 argmax를 그대로 쓰면 "Reach To Shelf"와 "Hand In Shelf"처럼 시각적으로
비슷한 행동 사이에서 라벨이 떨립니다. 최근 5개 예측의 다수결을 쓰고 신뢰도는
승자 예측들의 평균으로 계산합니다 (`runtime.smooth_window`).

### 5.3 최소 신뢰도 임계값

`runtime.min_action_conf: 0.4`. 이보다 낮으면 라벨을 표시하지 않습니다.
논문에는 없는 값이며, 실사용에서 틀린 라벨을 자신 있게 표시하는 것보다
표시하지 않는 편이 낫다는 판단입니다.

### 5.4 관절 유효성 기준

검출 점수 0.2 이하인 관절은 좌표를 0으로 만들고, 윈도우 전체에서 유효 관절 비율이
30% 미만이면 분류를 건너뜁니다. 논문에 없는 값입니다.

## 6. 하드웨어와 양자화

### 6.1 양자화 경로

논문은 float32 PyTorch 모델을 **int8 TFLite**로 변환합니다(§3, §5). TFLite는 일반
엣지 보드에는 타당하지만 Jetson에서는 GPU를 쓰지 않습니다. 두 경로를 모두
구현했습니다.

| 경로 | 대상 | 비고 |
|---|---|---|
| TensorRT FP16/INT8 | Jetson **(권장)** | GPU 사용, JetPack 기본 포함 |
| int8 TFLite | 논문 재현 | `onnx2tf` + `tensorflow` 필요 |
| PyTorch dynamic int8 | 툴체인 없는 CPU | Linear/LSTM만 양자화 |
| ONNX | 중간 포맷 | 위 모든 경로의 입력 |

행동 모델은 35만~102만 파라미터로 작아서 양자화 이득이 제한적입니다.
실제로 fps를 좌우하는 것은 pose 모델이므로 그쪽을 먼저 변환하십시오.

### 6.2 하드웨어 차이

논문은 Jetson AGX Xavier 32GB(512-core Volta, CUDA 11.4)를 씁니다.
이 저장소는 Jetson Orin NX 16GB(JetPack 6.2, CUDA 12.6)에서 검증했습니다.
보드가 다르므로 논문 표 4.5의 fps·메모리 수치와 직접 비교되지 않습니다.
비교하려면 `tools/benchmark.py`를 양쪽에서 돌리십시오.

## 7. 논문에서 확인되지 않는 점

구현하면서 논문 서술과 맞지 않거나 검증할 수 없었던 부분입니다.

### 7.0 표 4.3의 클래스 분포가 실제 데이터와 다릅니다

MERL Shopping 데이터셋을 실제로 내려받아 106개 라벨 파일 전부를 집계한 결과입니다.

```bash
.venv/bin/python -c "
from car.datasets.merl import _load_tlabs
from pathlib import Path
import numpy as np
files = sorted(Path('data/raw/merl/labels').glob('*_label.mat'))
frames = np.zeros(5, np.int64)
for f in files:
    for i, a in enumerate(_load_tlabs(f)):
        if len(a): frames[i] += int((a[:,1]-a[:,0]+1).sum())
print(frames // 3)   # 30fps -> 10fps
"
```

| 클래스 | 실제 (10 fps 환산) | 논문 표 4.3 |
|---|---|---|
| Reach To Shelf | 19,680 | 24,989 |
| Retract From Shelf | 20,124 | 25,302 |
| Hand In Shelf | 11,931 | 25,999 |
| Inspect Product | 25,968 | 24,301 |
| Inspect Shelf | 34,400 | 25,749 |
| **합계** | **112,104** | **126,340** |

**실제 데이터는 심하게 불균형합니다.** 가장 흔한 "Inspect Shelf"가 가장 드문
"Hand In Shelf"의 2.9배입니다. 논문 표 4.3은 24,301~25,999로 거의 균등하다고
보고하며 "각 행동 클래스가 비교적 균등하게 분포되어 모델 학습의 편향을
최소화하도록 설계하였다"고 서술합니다. "설계하였다"는 표현으로 보아 의도적으로
균형을 맞춘 것으로 보이지만, 그 방법은 밝히지 않았습니다.

이 구현은 `train.balance_ratio`로 다수 클래스의 학습 윈도우를 최소 클래스의
배수로 제한합니다. 검증 세트는 균형을 맞추지 않습니다. 실제 분포에서 모델이
어떻게 동작하는지 가려지기 때문입니다.

### 7.1 그 밖의 불일치

1. **혼동행렬의 샘플 수 불일치.** 그림 4.2(a) LSTM 혼동행렬은 제목에
   "120,000 samples per label"이라고 되어 있고 행 합이 약 120,000인데,
   표 4.3의 클래스별 총 프레임 수는 약 25,000입니다. (b) ST-GCN 혼동행렬은
   표 4.3과 일치합니다.

2. **본문과 그래프의 수치 차이.** 그림 4.3 그래프의 LSTM(Desktop) 정확도는
   0.87인데 표 4.4는 0.85입니다.

3. **"약 6% 향상"의 기준.** 표 2.1은 mAP50 0.84→0.90(+7.1% 상대),
   mAP50-95 0.63→0.66(+4.8% 상대)인데 본문은 각각 "약 3%", "약 6%"라고 합니다.
   절대 차이(0.06, 0.03)를 백분율로 쓴 것으로 보이며 서술과 순서가 뒤바뀌어
   있습니다.

4. **표 번호 중복.** 15쪽과 7쪽이 모두 "표 2.1"입니다.

이 항목들은 구현에 영향을 주지 않지만, 결과를 논문 수치와 대조할 때 염두에
두어야 합니다.
