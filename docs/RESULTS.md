# 실험 절차 및 결과 요약

- 대상 논문: 노재현, 「온디바이스에서의 Skeleton 기반 고객 행동 인식 모델 개발」, 한신대학교 석사학위논문, 2025
- 목적: 논문 전체 파이프라인의 실행 가능한 재현 및 검증
- 측정 장비: NVIDIA Jetson Orin NX 16GB (JetPack 6.2, CUDA 12.6, 전력 모드 25W)
- 데이터: MERL Shopping Dataset (영상 106개, 라벨 106개)

---

## 1. 실험 절차

### 1.1 전체 흐름

| 단계 | 작업 | 산출물 | 소요 |
|---|---|---|---|
| 1 | 데이터셋 확보 | 영상 106개 (1.8 GB) + 라벨 106개 | 10분 |
| 2 | 1차 skeleton 추출 (COCO pose) | 91,168 프레임 | 72분 |
| 3 | 1차 행동 모델 학습 | ST-GCN 0.574 / LSTM 0.602 | 30분 |
| 4 | pose 자동 라벨링 | 12관절 라벨 10,347장 | 77분 |
| 5 | Custom YOLOv11n-Pose 학습 | mAP50 0.927 | 55분 |
| 6 | 2차 skeleton 추출 (Custom pose) | 134,898 프레임 | 117분 |
| 7 | 2차 행동 모델 학습 | ST-GCN 0.701 / LSTM 0.694 | 57분 |
| 8 | 양자화 및 추적 평가 | int8 모델, 추적 지표 | 40분 |

### 1.2 단계별 명령

| 단계 | 명령 |
|---|---|
| 데이터 다운로드 | `curl -LO https://www.merl.com/pub/tmarks/MERL_Shopping_Dataset/Videos_MERL_Shopping_Dataset.zip` |
| skeleton 추출 | `tools/extract_skeletons.py --merl data/raw/merl --fps 10 --keep-background` |
| pose 라벨링 | `tools/autolabel_pose.py --teacher weights/yolo11x-pose.pt --fps 1 --conf 0.6` |
| pose 학습 | `car.train.train_pose --data data/processed/pose_dataset/dataset.yaml` |
| 행동 학습 | `car.train.train_action --model stgcn --set train.balance_ratio=1.5` |
| 평가 | `car.train.evaluate --checkpoint runs/action/*/best.pt` |
| 추적 평가 | `tools/eval_tracking.py --merl data/raw/merl --clips 12` |
| 양자화 | `tools/export_models.py --checkpoint ... --format torch-int8` |

| 항목 | 값 | 출처 |

## 2. 실험 결과

### 2.1 자세추정 (논문 표 2.1 대응)

| 지표 | 논문 기존 | 논문 Custom | 본 구현 Custom |
|---|---|---|---|
| mAP-pose 50 | 0.84 | 0.90 | **0.927** |
| mAP-pose 50-95 | 0.63 | 0.66 | **0.885** |
| mAP-box 50 | - | - | 0.995 |

- 학습 데이터: 교사 모델(yolo11x-pose) pseudo-label 10,347장
- 학습 조건: 480 px, batch 24, 15 epoch 수렴
- 주의: pseudo-label 기준 수치이며 사람이 라벨링한 정답 대비 값이 아님

**동일 프레임 비교**

| 모델 | 검출 | 평균 관절 신뢰도 | 추론 지연 |
|---|---|---|---|
| 기존 YOLOv11n-Pose | 1명 | 0.924 | 69 ms |
| Custom YOLOv11n-Pose | 1명 | **0.976** | **47 ms** |

### 2.2 추출 데이터 품질

| 항목 | 기존 pose | Custom pose | 증감 |
|---|---|---|---|
| 검출 프레임 | 91,168 | 134,898 | +48% |
| 30프레임 윈도우 | 8,279 | 25,627 | +210% |
| 학습 윈도우 (균형 후) | 5,971 | 11,046 | +85% |

- Custom pose는 상단 시점에서 검출이 끊기지 않아 트랙이 길게 유지됨
- 정확도 개선보다 **연속성 확보**가 행동 인식에 더 크게 기여

### 2.3 행동 인식 (논문 표 4.4 대응)

| Metric | ST-GCN | LSTM | 논문 ST-GCN | 논문 LSTM |
|---|---|---|---|---|
| Accuracy | 0.701 | 0.694 | 0.93 | 0.85 |
| Macro precision | 0.69 | 0.68 | 0.90 | 0.83 |
| Macro recall | 0.69 | 0.68 | 0.85 | 0.83 |
| Mean F1 | 0.69 | 0.68 | 0.90 | 0.82 |
| Parameters | 1,018,413 | 353,549 | 922,301 | 352,775 |
| 학습 시간 | 3,147초 | 283초 | - | - |

**Custom pose 적용 효과**

| 모델 | 기존 pose | Custom pose | 개선 |
|---|---|---|---|
| ST-GCN | 0.574 | 0.701 | **+12.7%p** |
| LSTM | 0.602 | 0.694 | **+9.2%p** |

### 2.4 분할 단위의 영향

- 동일 데이터·모델·하이퍼파라미터에서 분할 단위만 변경

| 분할 단위 | val accuracy | 비고 |
|---|---|---|
| 윈도우 단위 (무작위) | 0.70 | 인접 윈도우가 25프레임 공유 → 누수 |
| 클립 단위 | 0.57 | 검증 클립은 미학습 |

- 차이 13%p
- 논문은 "70%/30%"만 명시하고 단위 미기재
- 표 4.3이 클래스별 **프레임 수**를 제시 → 프레임 단위 분할 가능성

### 2.5 추적 성능 (논문 표 2.2 대응)

- 평가 대상: 공식 테스트 피험자 12개 클립
- 평가 기준: 프레임당 "사용 가능한 skeleton 산출 여부" (MERL은 1인 촬영)

| Metric | Pose only | with StrongSORT | 논문 delta |
|---|---|---|---|
| Accuracy | 0.924 | 0.921 | 논문 +0.06 |
| Recall | 0.926 | 0.922 | 논문 +0.07 |
| F1-score | 0.961 | 0.959 | 논문 +0.06 |
| ID switches | - | 38 | - |

- **논문의 +6%p 향상을 재현하지 못함**
- 원인 추정
  - MERL은 1인 촬영 → 추적이 추가로 잡을 대상이 없음
  - Custom pose가 이미 92.4% 검출 → 개선 여지 협소
  - `n_init=3` 조건으로 클립 초반 3프레임 손실
- 추적의 실질적 가치는 **다중 인물 시나리오**와 **트랙별 버퍼 분리**에 있음

### 2.6 양자화 (논문 §3 대응)

- 논문: float32 → int8 TFLite
- 본 구현: PyTorch dynamic int8 (Jetson은 TensorRT가 더 적합)

| 모델 | 정밀도 | Accuracy | 모델 크기 | CPU 지연 |
|---|---|---|---|---|
| LSTM | fp32 | 0.746 | 1.42 MB | 36.0 ms |
| LSTM | int8 | 0.748 | **0.39 MB** | 73.6 ms |
| ST-GCN | fp32 | 0.757 | 4.13 MB | 376 ms |
| ST-GCN | int8 | 0.757 | 4.13 MB | 402 ms |

- LSTM: 크기 **73% 감소**, 정확도 유지
- LSTM: CPU 지연 **2배 증가** (qnnpack이 Orin ARM에 미최적화)
- ST-GCN: 효과 없음 (dynamic 양자화는 Linear/LSTM만 대상, ST-GCN은 Conv2d 기반)
- 실제 배포는 GPU 경로이므로 CPU int8의 실익 제한적

### 2.7 온디바이스 성능 (논문 표 4.5 대응)

**행동 모델 단독**

| 모델 | 파라미터 | 지연 | 처리율 |
|---|---|---|---|
| ST-GCN | 1,018,413 | 8.70 ms | 115 Hz |
| LSTM | 353,549 | 3.49 ms | 286 Hz |

**자세추정 단독 (640 px, 4인 프레임)**

| 백엔드 | 지연 | fps |
|---|---|---|
| PyTorch FP32 | 101 ms | 9.9 |
| PyTorch FP16 | 89 ms | 11.2 |
| TensorRT FP16 | 45 ms | 22.3 |
| Custom pose FP32 | 40 ms | 24.8 |

**전체 파이프라인 (920×680 MERL 영상)**

| 구성 | fps | 자세추정 | 추적 | 행동분류 |
|---|---|---|---|---|
| Custom pose + LSTM | **23.9** | 38.8 ms | 0.8 ms | 0.9 ms |
| Custom pose + ST-GCN | 22.7 | 39.2 ms | 0.8 ms | 2.7 ms |
| 기존 pose + ST-GCN (TensorRT) | 18.6 | 24.5 ms | 3.7 ms | 15.1 ms |

**논문 대조**

| 항목 | 논문 (AGX Xavier 32GB) | 본 구현 (Orin NX 16GB, 25W) |
|---|---|---|
| Pose + LSTM fps | 32 | 23.9 |
| Pose + ST-GCN fps | 28 | 22.7 |
| 프로세스 메모리 | 5.8–7.2 GB / 32 GB | 1.3–1.5 GB / 16 GB |

- LSTM이 ST-GCN보다 빠르다는 **경향은 재현**
- 절대값은 보드 상이(512-core Volta vs Orin NX) 및 전력 모드 제한으로 직접 비교 불가

## 3. 기존 논문과 변경된 점

### 3.1 논문 미기재 항목의 결정

| 항목 | 논문 | 본 구현 | 근거 |
|---|---|---|---|
| Skeleton 정규화 | 미기재 | 몸통 기준 (torso) | 측정: torso 0.849 > bbox 0.831 > 없음 0.644 |
| 학습 데이터 증강 | 미기재 | 회전 ±30°, 스케일 ±15% | 측정: ±30° 0.839 > ±180° 0.784 > 없음 0.730 |
| train/val 분할 단위 | "70/30"만 명시 | 클립 단위 | 프레임/윈도우 단위는 25프레임 중복 누수 |
| 윈도우 라벨 결정 | 미기재 | 마지막 프레임 | 실시간 추론 조건과 일치 |
| grouped conv 그룹 수 | "grouped convolution" | 2 | 논문 파라미터 922,301개에서 역산 |
| LSTM Dense 폭 | 미기재 | 32 | 논문 파라미터 352,775개에서 역산 |
| StrongSORT ReID | 미기재 | HSV 색 히스토그램 | 온디바이스에 2차 신경망 배제 |
| pose 라벨 제작 | "YOLO 포맷 이용" | 대형 모델 pseudo-labeling | 126,350장 수작업 비현실적 |
| 최소 행동 신뢰도 | 미기재 | 0.40 | 오라벨 표시보다 미표시가 안전 |
| 예측 평활화 | 미기재 | 최근 5개 다수결 | 유사 행동 간 라벨 떨림 억제 |

### 3.2 구현 과정에서 추가한 것

| 항목 | 내용 | 이유 |
|---|---|---|
| 단일 트랙 병합 | 클립당 1명으로 병합 | 트랙 끊김으로 윈도우 생성 실패 |
| 프레임 간격 허용 | `max_gap` 6 → 12 | 연속 3프레임 미검출까지 시퀀스 유지 |
| 클래스 균형 상한 | `balance_ratio` | 실데이터 클래스 2.9배 불균형 |
| 데이터셋 공식 split | 피험자 1-20/21-26/27-41 | 발표 수치와 비교 가능성 확보 |
| TensorRT 경로 | Jetson 기본 배포 형식 | TFLite는 Jetson GPU 미사용 |

- 논문 서술: "각 행동 클래스가 비교적 균등하게 분포되어... 설계하였다"

## 4. 논문에 쓸 수 있는 유효한 내용

### 4.1 재현에 성공한 항목

| 항목 | 논문 | 본 구현 | 판정 |
|---|---|---|---|
| Custom pose 학습으로 mAP 향상 | 0.84 → 0.90 | 0.927 달성 | **재현** |
| LSTM이 ST-GCN보다 경량·고속 | 파라미터 60만 차이 | 66.5만 차이, 2.5배 빠름 | **재현** |
| 온디바이스 실시간 동작 | 28~32 fps | 22.7~23.9 fps | **재현** |
| Reach/Retract 간 혼동 | 본문 서술 | 혼동행렬에서 최대 오류 | **재현** |
| int8 양자화로 모델 축소 | TFLite | LSTM 73% 감소 | **부분 재현** |

### 4.2 재현하지 못한 항목

| 항목 | 논문 | 본 구현 | 원인 |
|---|---|---|---|
| 행동 인식 정확도 | ST-GCN 0.93 | 0.70 | 분할 단위 + 미기재 전처리 |
| StrongSORT 성능 향상 | +6%p | -0.3%p | 1인 촬영 + 평가 기준 상이 |
| ST-GCN > LSTM 우위 | +8%p | +0.7%p | 데이터 조건 차이 |

### 4.3 본 연구가 추가로 밝힌 것

| 발견 | 정량 근거 | 시사점 |
|---|---|---|
| 분할 단위가 정확도를 크게 좌우 | 클립 0.57 vs 윈도우 0.70 | 재현 시 분할 단위 명시 필수 |
| Custom pose의 기여는 연속성 | 윈도우 3.1배 증가 | mAP보다 검출 안정성이 중요 |
| 실데이터는 클래스 불균형 | 최대/최소 2.9배 | 균형 조정 전략 필요 |
| 추적기 버그: cascade 누락 | 단위 테스트로 검출 | appearance 없이도 cascade 필수 |
| ARM에서 int8이 느려질 수 있음 | LSTM 36 → 74 ms | 양자화는 목표 하드웨어에서 검증 |
| Jetson torch 설치 함정 | CPU 전용 휠 자동 선택 | 인덱스 단독 지정 + `--no-deps` |
