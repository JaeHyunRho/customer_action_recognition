# A. 설계 선택 실험 (합성 데이터)

## 1. 회전 augmentation 범위

- **질문**: 천장 카메라는 방향성이 없으니 360° 회전이 맞는가?
- **가설**: 카메라와 선반이 고정이면 접근 방향이 제한되므로 무제한 회전은 신호를 지움

```bash
.venv/bin/python -m car.train.train_action --store data/processed/demo_skeletons.npz \
  --model stgcn --set train.epochs=40 train.aug_rotation_deg=30
```

| 조건 | Accuracy | Macro F1 | Best epoch |
|---|---|---|---|
| 증강 없음 | 0.730 | 0.721 | 16 |
| **회전 ±30°** | **0.839** | **0.835** | 31 |
| 회전 ±180° | 0.784 | 0.776 | — |

- 증강 없음: 16 epoch에 과적합 시작
- ±180°: "팔이 선반 쪽으로 뻗었다"는 방향 정보 소실
- **채택**: `train.aug_rotation_deg: 30`

## 2. Skeleton 정규화 방식

| 방식 | 처리 | Accuracy | Macro F1 |
|---|---|---|---|
| **`torso`** | 엉덩이 중점 이동, 몸통/어깨 최대값으로 나눔 | **0.849** | **0.847** |
| `bbox` | 박스 원점 기준, 박스 크기로 나눔 | 0.831 | 0.831 |
| `none` | 프레임 크기로만 나눔 | 0.644 | 0.640 |

- 정규화 없으면 프레임 내 위치에 따라 입력이 달라져 0.644로 급락
- `bbox`는 박스 검출 품질에 연동되어 불안정
- **채택**: `sequence.normalize: torso`
- 부가 이점: 카메라 높이가 바뀌어도 동일 입력 → 타 매장 배포 시 재학습 부담 감소

## 3. 윈도우 라벨 결정 방식

- **질문**: 30프레임 윈도우가 두 행동에 걸칠 때 어느 라벨을 쓰는가?

| 방식 | Accuracy | 학습/검증 윈도우 |
|---|---|---|
| **`last`** | **0.839** | 935 / 385 |
| `majority` | 0.953 | 935 / 385 |
| `drop_mixed` | 1.000 | 263 / 110 |

- **숫자가 높은 쪽을 고르면 안 되는 사례**
- `drop_mixed` 1.000: 전이 구간을 버려 학습 데이터가 1,320 → 373으로 감소, 문제 자체가 쉬워짐
- `majority`: 학습은 쉬우나 실시간 추론 조건("지금 무엇을 하는가")과 불일치
- **채택**: `last` — 세 방식 중 가장 낮지만 실배포를 정직하게 반영

## 4. ST-GCN grouped convolution 그룹 수

- 논문 파라미터 922,301개에서 역산 (학습 불필요, 구조만으로 계산)

| groups | 파라미터 | 논문 대비 |
|---|---|---|
| 1 | 1,983,021 | +115% |
| **2** | **1,018,413** | **+10.4%** |
| 4 | 535,725 | -41.9% |
| 8 | 294,573 | -68.1% |

- 정확히 맞지 않는 이유: 논문이 시간축 커널 크기 미기재
- `temporal_kernel=7`이면 846,381개로 논문보다 작아짐
- **채택**: `stgcn.groups: 2`
- LSTM은 `dense_hidden=32`에서 353,549개 → 논문(352,775) 대비 +0.2%

## 5. 추적기 appearance descriptor

| descriptor | 추적 지연 | 추가 모델 | 적합 상황 |
|---|---|---|---|
| `none` | 최저 | 없음 | 1인 촬영 |
| **`histogram`** | 낮음 | 없음 | 옷 색 다른 소수 인원 |
| `reid` | 높음 | ReID 망 | 혼잡, 옷 색 유사 |

- **채택**: `tracker.appearance: histogram`
- **버그 발견**: appearance 없을 때 matching cascade를 건너뛰면 미검출 트랙이 영구 복구 불가
  - 단위 테스트 `test_track_id_survives_a_gap_shorter_than_max_age`가 검출
  - cascade가 motion-only 비용으로도 동작하도록 수정

# B. 실데이터 결과 (MERL Shopping, 피험자 분할)

- 데이터 출처: `https://www.merl.com/pub/tmarks/MERL_Shopping_Dataset/`
- 규모: 영상 106개 (1.8 GB) + 라벨 106개, 피험자 41명
- 프로토콜 원문: `runs/subject_split/PROTOCOL.md` / 전체 표: [RESULTS.md](RESULTS.md)

## 6. 평가 프로토콜

**이전 방식의 문제**

| 문제 | 내용 |
|---|---|
| 테스트셋 없음 | 한 파일을 클립 단위로 나눠 검증 best epoch의 정확도를 보고 |
| pose 누수 | pose pseudo-label에 106개 영상 전체가 들어가, 검증 클립의 프레임을 pose 모델이 학습 |
| pose 검증 분할 | 프레임을 20% 확률로 검증에 배정 → 같은 영상의 프레임이 양쪽에 존재 |
| mAP 오독 | 문서의 mAP50 0.927 / mAP50-95 0.885는 로그의 recall / mAP50 열을 한 칸 밀려 읽은 값 |
| 팔 관절 σ 미적용 | `OKS_SIGMA`를 덮어쓰는 방식은 12관절 모델에서 효과가 없었음 |

**현재 방식**

| 항목 | 내용 |
|---|---|
| 분할 | 학습 피험자 1–20 (60편), 검증 21–26 (18편), 테스트 27–41 (28편) |
| pose 학습 | 피험자 1–20만. pose 검증은 영상 단위 12편 |
| 가중치 갱신 / 조기 종료 / 테스트 | 학습 파일만 / 검증 accuracy만 / best checkpoint로 1회 |
| seed | 42, 43, 44 모두 보고 |
| 신뢰구간 | 피험자 15명 bootstrap (seed 평균), 모델 비교는 paired bootstrap |
| 팔 관절 σ | `dataset.yaml`의 `kpt_oks_sigmas`로 손실과 검증에 실제 반영 |

```bash
.venv/bin/python tools/run_subject_split.py     # 전처리 → 학습 → 채점, 작업 75개
.venv/bin/python tools/subject_split.py report  # 집계
```

## 7. Custom YOLOv11n-Pose 재학습

```bash
.venv/bin/python tools/autolabel_pose.py --videos data/raw/merl/videos \
  --out data/processed/pose_dataset_s1_20 --teacher weights/yolo11x-pose.pt \
  --fps 1 --conf 0.6 --min-keypoints 8 --subjects 1-20 --val-ratio 0.2 --seed 42
```

| 항목 | 값 |
|---|---|
| 교사 모델 | YOLOv11x-Pose |
| 채택 라벨 | 5,780장 (기각 2,370장) |
| 학습 / 검증 | 4,581장 (48편) / 1,199장 (12편) |
| 학습 조건 | 480 px, batch 24, 40 epoch (best 40) |
| OKS σ | 어깨 0.0527, 팔꿈치 0.048, 손목 0.0413 (COCO 값 ÷ 1.5), 엉덩이·무릎·발목은 COCO 값 |

| 교사 일치도 (pose 검증 1,199장) | 값 |
|---|---|
| box mAP50 / mAP50-95 | 0.995 / 0.933 |
| pose precision / recall | 0.913 / 0.912 |
| pose mAP50 / mAP50-95 | 0.879 / 0.434 |

- 교사 pseudo-label과의 일치도이며 사람 라벨 정답 대비 값이 아님
- 평가 σ가 표준 COCO 표가 아니므로 다른 문헌의 mAP와 비교 불가
- mAP50-95가 낮다는 것은 학생이 교사의 관절 위치를 엄격한 기준으로는 재현하지 못한다는 뜻. 그럼에도 행동 인식에서는 교사보다 높음 (§10)

## 8. 추출과 검출 연속성

| 분할 | 샘플 프레임 | Custom nano | 교사 yolo11x | COCO nano |
|---|---|---|---|---|
| 학습 | 81,230 | 92.0% | 83.7% | 63.1% |
| 검증 | 27,074 | 92.6% | 81.0% | 57.1% |
| 테스트 | 38,563 | 92.3% | 84.3% | 62.2% |

| Pose | 테스트 윈도우 | 간격이 벌어진 윈도우 | 정답 끝 프레임 채점 가능 비율 |
|---|---|---|---|
| Custom nano | 5,862 | 0.17% | 99.6% |
| 교사 yolo11x | 5,125 | 7.1% | 86.5% |
| COCO nano | 2,587 | 19.7% | 42.4% |

- 윈도우는 "저장된 검출 30개"이며 원본 프레임 간격 12까지 한 구간으로 연결. 결측이 없으면 2.9초, 측정된 최대는 4.5초
- Custom nano는 pose 학습에 쓰지 않은 테스트 피험자에서도 92%를 유지
- **학생(nano)이 교사(x)보다 더 많은 프레임에서 skeleton을 냄.** 교사는 COCO 시점으로 학습되어 상단 시점에서 검출이 끊기고, 학생은 교사가 확신한 프레임만으로 학습해 그 시점에 적응

## 9. E1: Custom skeleton 행동 인식

- 학습 윈도우 12,117 → 균형 후 8,783, 검증 4,196, 테스트 5,862

| 모델 | 테스트 정확도 (seed 42 / 43 / 44) | 평균 ± 표준편차 | macro-F1 | 피험자 평균 [95% CI] |
|---|---|---|---|---|
| ST-GCN | 0.6989 / 0.6965 / 0.6989 | 0.698 ± 0.001 | 0.683 | 0.699 [0.676, 0.719] |
| LSTM | 0.6940 / 0.6871 / 0.6929 | 0.691 ± 0.004 | 0.678 | 0.692 [0.663, 0.720] |

| 모델 | End-to-end (seed 42 / 43 / 44) | 평균 ± 표준편차 | 피험자 평균 [95% CI] |
|---|---|---|---|
| ST-GCN | 0.6909 / 0.6904 / 0.6943 | 0.692 ± 0.002 | 0.691 [0.670, 0.710] |
| LSTM | 0.6897 / 0.6819 / 0.6891 | 0.687 ± 0.004 | 0.687 [0.660, 0.715] |

**ST-GCN vs LSTM**

- 피험자별 paired 차이: 윈도우 +0.007 [−0.009, +0.021], end-to-end +0.004 [−0.012, +0.020]
- 구간이 0을 포함 → 차이가 확인되지 않음. 논문의 8%p 우위는 미학습 피험자에서 나타나지 않음
- 파라미터 2.9배(1,018,413 vs 353,549), 학습 시간은 GPU 공유 상태에서 약 2시간 vs 8분
- **온디바이스에서는 LSTM이 합리적**

**클래스별 F1 (seed 평균)**

| 클래스 | ST-GCN | LSTM |
|---|---|---|
| Reach To Shelf | 0.637 | 0.643 |
| Retract From Shelf | 0.662 | 0.670 |
| Hand In Shelf | 0.653 | 0.651 |
| Inspect Product | 0.697 | 0.669 |
| Inspect Shelf | 0.765 | 0.757 |

- Reach의 recall이 0.56–0.58로 가장 낮고, 20%가 직전 행동인 Inspect Shelf로 분류됨
- Retract ↔ Hand In Shelf (0.16–0.17), Inspect Product ↔ Inspect Shelf (0.13–0.21)
- 혼동은 시간상 이어지는 행동 사이에서 발생

## 10. E2: pose 모델 비교

**(a) 전체 skeleton — end-to-end**

| Pose | ST-GCN 윈도우 / end-to-end | LSTM 윈도우 / end-to-end |
|---|---|---|
| Custom nano | 0.698 / **0.692** | 0.691 / **0.687** |
| 교사 yolo11x | 0.639 / 0.548 | 0.649 / 0.562 |
| COCO nano | 0.544 / 0.233 | 0.536 / 0.227 |

- 윈도우 정확도는 각 pose가 만든 윈도우에서만 계산 → 검출 실패가 빠짐
- COCO nano는 윈도우 0.54인데 end-to-end 0.23. **pose 모델 비교에 윈도우 정확도를 쓰면 차이가 크게 과소평가됨**
- Custom − 교사 end-to-end 차이: ST-GCN +0.129 [0.092, 0.171], LSTM +0.096 [0.055, 0.148]

**(b) 교집합 — 세 pose가 모두 잡은 동일 프레임**

- 프레임 50,760 / 15,177 / 23,804, 윈도우 4,883(균형 후) / 1,644 / 2,569. 세 pose의 윈도우 구성이 동일

| Pose | ST-GCN | LSTM |
|---|---|---|
| Custom nano | 0.639 ± 0.004 | 0.648 ± 0.007 |
| 교사 yolo11x | 0.589 ± 0.025 | 0.618 ± 0.016 |
| COCO nano | 0.533 ± 0.009 | 0.551 ± 0.018 |

| paired 차이 | ST-GCN | LSTM |
|---|---|---|
| Custom − 교사 | +0.041 [0.015, 0.069] | +0.026 [0.006, 0.049] |
| Custom − COCO nano | +0.115 [0.084, 0.147] | +0.103 [0.071, 0.139] |
| 교사 − COCO nano | +0.075 [0.040, 0.113] | +0.078 [0.040, 0.114] |

**해석**

- 사전에 정한 판단 기준: "Custom과 교사가 비슷하면 기여는 상단 시점 적응이 아니라 경량 증류"
- 결과: 같은 프레임에서도 Custom이 교사보다 높고 구간이 0을 제외 → **경량 증류만으로는 설명되지 않음**
- 학생은 교사가 확신한 프레임만 보고 학습했지만, 교사가 놓치는 프레임까지 검출하고 공통 프레임에서도 분류에 더 유리한 skeleton을 냄
- 주의: 분류 정확도 기준의 비교. 관절 좌표의 정확도는 사람 라벨이 없어 측정하지 못함
- 교집합 정확도(0.64)가 Custom 전체(0.70)보다 낮은 이유: COCO nano가 놓친 프레임이 빠져 시퀀스에 간격이 생기고(윈도우의 19%), 학습 윈도우가 절반 수준. 교집합이 "쉬운 프레임"이라 높게 나올 것이라는 예상과 반대

**(c) 17관절 vs 12관절 (교사 skeleton, 같은 프레임)**

| 분류기 | 17관절 | 12관절 | 17 − 12 [95% CI] |
|---|---|---|---|
| ST-GCN | 0.647 ± 0.009 (0.6375 / 0.6494 / 0.6540) | 0.639 ± 0.016 | +0.016 [−0.008, +0.042], 9/15 |
| LSTM | 0.643 ± 0.007 (0.6445 / 0.6351 / 0.6482) | 0.649 ± 0.012 | +0.000 [−0.014, +0.014], 6/15 |

- 두 분류기 모두 차이의 95% 구간이 0을 포함. **머리 관절을 넣거나 빼는 것에 따른 정확도 차이는 확인되지 않음**
- 교사 출력에서 코·눈은 49–65%가 신뢰도 0.2 이하로 이미 0 처리되고, 귀는 6–8%만 0 처리됨
- COCO 계열 교사 pose에 대한 결과이며 Custom pose에 대한 주장이 아님

## 11. End-to-end 채점

- 분모: 테스트 28편의 `.mat` 라벨에서 10 fps 샘플 인덱스 `j % 5 == 0`인 끝 프레임 중 다섯 행동에 속하는 5,892개
- 끝 프레임마다 그 프레임에서 끝나는 최근 검출 30장(간격 ≤ 12)으로 윈도우를 직접 구성. 학습용 윈도우 목록과 매칭하지 않음
- 끝 프레임에 검출이 없거나 30장이 안 되면 오답

| Pose | 검출 없음 | 30장 미달 | 채점 가능 |
|---|---|---|---|
| Custom nano | 0 | 25 | 5,867 (99.6%) |
| 교사 yolo11x | 234 | 562 | 5,096 (86.5%) |
| COCO nano | 1,577 | 1,815 | 2,500 (42.4%) |

- 한계: 배경 구간에서 행동을 잘못 출력하는 경우는 분모에 없음
- 주 정확도는 윈도우별 argmax. 최근 5개 다수결과 신뢰도 0.4는 화면 출력용이라 수치에 넣지 않음

| Custom pose + LSTM | **20.7** | 40.4 ms | 1.9 ms | 4.7 ms | 47.1 ms | 1.28 GB |
| Custom pose + ST-GCN | 17.5 | 40.8 ms | 1.9 ms | 13.2 ms | 56.0 ms | 1.28 GB |

- 자세추정이 전체 지연의 73–86%를 차지. 행동 분류는 LSTM 4.7 ms, ST-GCN 13.2 ms (정규화와 배치 구성 포함)
- 교사 yolo11x는 nano 모델보다 약 5배 느려(210 ms, 4.7 fps) 온디바이스 실시간 처리에 부적합. Custom nano는 COCO nano와 같은 속도
- 측정 구간은 사람이 계속 등장하는 500프레임(테스트 영상 27_2의 원본 프레임 144부터)이며 분류기가 매 프레임 실행됨. 보드를 다른 프로세스와 공유하는 상태에서 측정
- 행동 모델은 10 fps 입력으로 학습되므로 실시간 실행 시 `--set runtime.max_fps=10`을 지정. 처리 속도는 그 요구치를 넘으면 충분
- Jetson은 GPU·CPU 메모리 공유 → 프로세스 RSS를 기준으로 보고
